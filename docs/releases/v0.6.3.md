# v0.6.3 — Route Intelligence

- **Date:** 2026-11-21
- **Scope:** Route workspace, geometry display smoothing and route-level official evidence
- **Status:** Complete, not committed

## 1. Goal

Turn route selection into a real investigation surface: one route number connects the GTFS
map, live buses, current alerts, official historical metrics, seasonality and an
evidence-based “What Changed?” summary.

Also fix the jagged line appearance reported on the Live Network map without changing the
source GTFS shape data.

## 2. Geometry display fix

The imported shape points are real GTFS road geometry, but many consecutive points are
sub-metre apart and road corners are drawn as hard joins by Leaflet. We added a display-only
pipeline:

```text
GTFS shape points
  -> remove sub-metre duplicates
  -> Douglas–Peucker simplification (5 m tolerance)
  -> conservative corner rounding (9 m radius, 22° minimum turn)
  -> Leaflet polyline
```

The API and database still keep the original ordered shape points. Nothing is rewritten in
GTFS tables, and the smoothing is not presented as new source data.

New file:

```text
frontend/src/lib/geometry.ts
frontend/src/lib/geometry.test.ts
```

Tests verify:

- collinear points collapse to a straight segment
- sharp corners are rounded while endpoints are preserved
- short/simple lines are not altered

## 3. Backend additions

Added one read-only endpoint:

```text
GET /api/v1/analytics/routes/{route_no}/intelligence
```

It returns:

- official route name
- GTFS route IDs and match status
- per-metric changes for punctuality, reliability and boardings
- latest / previous observed month and value
- rolling 12-month average
- sample months and sufficiency
- full monthly series for seasonality
- warnings when a route's series uses more than one AT report family

No existing API response was removed or changed.

New service function:

```text
backend/app/analytics/service.py::route_intelligence
```

New test:

```text
backend/tests/test_analytics_api.py::test_route_intelligence_uses_official_rows_and_gtfs_mapping
```

## 4. Route Intelligence page

`/routes/:routeNo` now includes:

- official route search
- route context synced with URL and shared with other modules
- GTFS geometry and ordered stops on a Leaflet map
- live vehicles for the matched GTFS route
- current bus service alerts
- metric strip: observed months, latest punctuality, latest boardings, current buses
- “What Changed?” evidence cards
- punctuality / reliability / boardings trend summaries
- seasonality heatmap for the selected route
- explicit warnings for:
  - no GTFS match
  - no official data
  - mixed report families
  - missing current predictions

The summary language is deliberately conservative: it compares observed months and does
not claim causation or invent targets.

## 7. Known limitations

- Historical metrics remain monthly and route-level, not stop-level.
- Live bus positions remain current-state only; no historical vehicle replay exists.
- Multiple GTFS route IDs for one official route number are not selectable individually;
  the first match is used for the map.
- The “What Changed?” summary compares latest vs previous observed month; it does not
  model seasonality-adjusted change.
- Route Comparison is still a shell and arrives in v0.6.6.
